# 事务与 Undo 差分证据

**当前尚未实现 committed-only 卸载。** 已落地的是普通行事务尾、部分 Undo 公共头的
验证和有界追踪。不能把“有 slot”“删除位为 0”“无 Roll 地址”或“ROLL 中没找到事务号”
当作提交证明。

## 本轮实验

2026-09-06 在 DM8 测试机创建独立 `UNDOLAB` 实例，8 KiB 页、16 页簇、UTF-8，
DM8 build `03134284336-20250117-257733-20132`。没有停止原有数据库实例。
实验初期 DM9 测试机 SSH 超时；后续已恢复连接并完成其他兼容性矩阵，但以下新增 Undo
结构结论仍未完成 DM9 独立复核。

表为 `SYSDBA.UNDO_PROBE(ID INT PRIMARY KEY, VALUE_TX VARCHAR(100))`。两个独立会话分别
负责 DML 和观察其他会话可见的数据。每阶段执行 Checkpoint 后暂停该独立实例进程复制
SYSTEM/MAIN/ROLL，再恢复运行。这些是用于差分的落盘样本，**不是正常停库的冷备份**。

| 阶段 | 物理证据 |
| --- | --- |
| 初始 3 行提交 | 普通行尾事务号 6780，无 Roll 地址 |
| INSERT 未提交 | 新行 99 的事务号 6782，无 Roll 地址；另一会话看不到 |
| INSERT 提交 | MAIN page 16 与未提交时完全相同；变化发生在 ROLL 页 |
| 第一次 UPDATE | 当前行引用 `file=0,page=447,offset=55`，前事务号 6780 |
| 第二次 UPDATE | 当前行引用 `0:447:117`，再链接到 `0:447:55` |
| DELETE 未提交 | 行首最高位设置，尾部指向 `0:447:234`；另一会话仍可见原行 |
| Rollback | 当前 slot 指回恢复后的值；旧物理行仍残留，Undo used-end 回到起点 |
| DELETE 提交 | 删除位仍在；ROLL page 447 已被新事务 6784 复用 |

提交 INSERT 后，ROLL page 447 的事务号可能清零，而不是保留“6782 已提交”的稳定记录。
ROLL `0x24` 类管理页 page 87 也同步变化。其完整目录、事务状态枚举、复用边界及多文件
完整性尚未验证，因此不能仅扫描所有 `0x1D` 页的事务号来推导全库已提交集合。

DELETE 样本还确认 `n_rec` 可以包含已标删除但仍有 slot 的行。页检查使用物理行跨度约束
计数，不把这一差异直接报告为坏块；普通卸载仍跳过删除行。

## 已验证的 Undo 公共头

以下偏移以 **ROLL 页内** 为基准，仅描述上述 build 的样本：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| `0x14` | 4 | 页类型 `0x1D`，LE |
| `0x24` | 6 | 当前所属事务号，LE48 |
| `0x2A` | 1 | 原始状态字节，尚未作为提交判断使用 |
| `0x2B` | 2 | used-start，LE16；本样本为 55 |
| `0x2D` | 2 | used-end，LE16 |

以下偏移以 **Undo 记录起点** 为基准：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| `0` | 2 | 物理记录长度，LE16 |
| `2` | 1 | 本次观察到 INSERT=1、UPDATE=2、DELETE=3 |
| `3` | 1 | 布局标记，本次接受 `2/3`；其他值拒绝 |
| `4` | 4 | 操作序号，LE32 |
| `8` | 6 | 前版本事务号，LE48 |
| `20/24` | 各 4 | 两个对象标识；本实验均为表 ID 1017，保留两者，不假设恒等 |
| `28` | 1 | 前 Roll file |
| `29` | 4 | 前 Roll page，LE32 |
| `33` | 2 | 前 Roll offset，LE16 |
| `35` | 6 | 聚簇行号，LE48 |
| `43` 至尾部前 2 字节 | 可变 | 操作 payload；尚未通用地还原为列值补丁 |
| 最后 2 字节 | 2 | 记录自身页内偏移，LE16 |

`scan storage;` 的样例报告会优先保留带 Undo 地址的 slot 行，并输出追踪摘要，例如：

```text
0:447:117 UPDATE seq=12 previous_trx=6783
 -> 0:447:55 UPDATE seq=6 previous_trx=6780
 -> END (visibility unknown)
```

追踪逐步校验页身份、页类型、事务号、used 区间、记录长度、自身偏移、聚簇行号和对象标识。
最多追踪 128 层；缺失、复用、冲突、未知格式或循环会留下 STOP 原因。
这些检查不是完整 ROLL 校验器，报告本身不保证事务一致性。

## 完成 committed-only 前的条件

1. 解码 `0x24` 管理页及其上层目录，证明活动事务集合完整，处理缺失 ROLL 文件。
2. 验证 ACTIVE、预提交、提交、回滚、已回收等状态及跨文件/跨页 generation 关系。
3. 解码完整 UPDATE 列补丁，覆盖固定列、NULL、主键变化、LOB/Long Row、历史列版本。
4. 完成 DELETE/INSERT 反向处理、Savepoint、多会话、多页 Undo、实例崩溃后的差分验证。
5. 在 DM8/DM9 不同页大小和字符集下，对照在线一致性读结果。

在这些条件满足前，不把普通 `unload` 切换成自动 Undo 应用，也不对未知事务作“默认已提交”推断。

实验脚本：`research/undo_lab_capture.py`，凭据通过环境变量传入；它限制实例路径和端口，
拒绝覆盖已有快照。原始 DBF 不进入公开仓库。官方事务概念见
[事务管理](https://eco.dameng.com/document/dm/zh-cn/pm/management-affairs.html)，官方没有在此
公开上述磁盘偏移，这些偏移属于实验验证结果。
